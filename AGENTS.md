## Canonical vocabulary

```text
Actor = who acts
Mold = how that Actor is represented and verified
Gummy = what the Actor creates or operates
Bowl = where Actors and Gummies gather
Link = how they relate
Grab = how a Gummy becomes yours without altering the source
```

Protocol 0.1 terms Snack, Drop, Fork, Snack Bar, and Snack Graph are legacy implementation inputs. They are not current product language.

## Active mission

Make **Personal Gummy OS** dependable.

The controlling exit is:

```text
real file
→ real model route
→ bounded Actor Grant
→ result Gummy
→ truthful Action Receipt
→ survives return visits
```

Do not expand social, enterprise, federation, marketplace, or broad runtime scope before that exit passes.

## Non-negotiable constraints

- Preserve provider neutrality.
- Keep the desktop shell web-native and fast.
- Do not grant Actors or models ambient access.
- Actor is the authority principal.
- Mold is representation and verification, not authority.
- Do not treat Mold shape, color, handle, celebrity likeness, or character styling as authentication.
- Do not bypass browser framing policy.
- Do not hide network, model, connector, runtime, locality, or cost activity.
- Every consequential action must be representable as a Capability Grant and Action Receipt.
- The source Gummy must remain unchanged during a transformation task.
- A Grab creates a new Gummy and preserves `grab-of` provenance.
- Social sharing must have explicit audience, provenance, rights, and revocation behavior.
- Enterprise features use the same protocol objects as Personal Gummy OS with additional policy—not a separate incompatible product.
- Protocol 0.1 migration must be deterministic, idempotent, and non-destructive.
- Update architecture, protocol, and security documents whenever a feature changes a boundary or object model.

## Completion standard

A lane is complete only when:

- the user-visible path works;
- the authority and security boundary are explicit;
- protocol objects are typed;
- deterministic logic has tests;
- failure and denial are truthful;
- documentation matches code;
- source and result continuity survives return;
- `npm run verify` passes;
- the builder returns exact commits, tests, evidence, proven claims, unproven claims, and one next action.

The builder does not accept its own Return.
