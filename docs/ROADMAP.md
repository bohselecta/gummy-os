# Gummy Roadmap

The roadmap advances the whole product rather than hiding the social and enterprise opportunity behind an artificially tiny demo.

## Phase 0 — Repository and Protocol Recovery

**Goal:** establish a clean, runnable, authoritative base.

Delivered in this scaffold: web-native desktop, browser inside browser, demo chat, local object space, capability proof, receipts, Snack identity, Snack Graph proof, Enterprise Habitat proof, schemas, architecture/security/social/enterprise/business/licensing docs, tests, and CI.

Exit: `npm run verify` passes and the complete source exists on `main` after review.

## Phase 1 — Personal Gummy

**Goal:** make Gummy useful every day for one person.

IndexedDB metadata and OPFS bytes, project folders, import/export, trusted model broker, local model adapter, generated artifact writes, searchable receipts, installable PWA, accessibility, and polished full-screen onboarding.

Exit: a real file-to-agent-to-artifact task survives return visits.

## Phase 2 — Snack Graph

**Goal:** turn personal objects into a consent-first social system.

Passkey-backed Snacks, public/private profile separation, invitations, contacts, Bowls, Drops with audience/provenance/license/fork policy, replies, abuse controls, encrypted sync, Graph Inspector, and capability-bounded share links.

Exit: two users share and fork an object with clear ownership, audience, lineage, and revocation.

## Phase 3 — Governed Agent and Application Packs

**Goal:** prove safe operation of one real third-party application.

Production broker, signed grants and receipts, Pack authoring kit, typed capability runner, semantic interface map, workflow/recovery engine, verification harness, reference Pack, BrowserPod/Wasm adapter, and optional CheerpX evaluation.

Exit: an agent completes a vendor workflow inside an isolated capsule and returns a verified artifact.

## Phase 4 — Enterprise Habitat

**Goal:** make Gummy deployable by a real organization.

Organization identity, roles, OIDC/SAML, model and connector brokers, policy packs, approval chains, Pack registry, runtime manager, tenant boundaries, regions, signed receipts, hosted and dedicated-cloud editions, administration, and audit.

Exit: an organization can approve, execute, audit, revoke, and reproduce an agent-operated workflow.

## Phase 5 — Runtime Matrix

**Goal:** broaden compatibility without making every workload slow.

Web-native SDK, Wasm capsules, Linux compatibility, cloud container/VM adapters, GPU routing, snapshots, rollback, artifact gateways, compatibility catalog, performance budgets, and warm pools.

Exit: representative applications route across all runtime classes through one experience.

## Phase 6 — Federation and Fork Ecosystem

**Goal:** make Gummy a protocol rather than one compulsory service.

Signed Snack discovery, federated Bowl invitations, Drop exchange, fork lineage, compatibility declarations, key rotation, trust-domain moderation, self-hosting kit, branded editions, certification, and migration/export.

Exit: independent Gummy implementations exchange signed objects without one central account system.

## Phase 7 — Commercial Network

**Goal:** convert the protocol into durable revenue without taxing ordinary personal use.

Vendor integration program, certification, enterprise licensing, dedicated and sovereign deployment, managed brokers and runtime pools, OEM editions, long-term support, registry services, and partner program.

Exit: commercial customers pay for governance, reliability, compatibility, and deployment while Personal Gummy remains useful and free.
