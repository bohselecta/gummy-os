# Gummy OS Vision

## The proposition

A person should be able to open a URL, enter full screen, and arrive inside a complete creative computer where files, projects, conversations, applications, people, Agents, Actors, and shared work become understandable as one place.

Gummy OS is not one workflow and not one forced interface. It is a new medium: a playful WebOS canvas with explicit authority, containment, provenance, and connection to native intelligence.

People already understand windows, applications, files, dragging, opening, sharing, and trash. Gummy OS keeps that adoption advantage while changing what the computer can become:

- Actors persist at stable `@addresses`;
- Agents remain replaceable executable intelligence;
- Humans remain in Master Control;
- Molds define how a Human or Agent may embody and operate an Actor;
- Z is always available across the canvas;
- Gummies preserve ownership, provenance, and rights;
- recursive creation and composition are allowed;
- authority never inherits automatically;
- consequential work and boundary crossings leave evidence;
- native security and enterprise controls stay where they already work.

## The existing two-layer foundation

The native AI Linux distribution already exists locally. It is a usable Linux system with optional AI system control, a native chat/control surface, and live-USB work.

Gummy OS is the WebOS that can run inside that distribution or independently on an ordinary computer or phone.

```text
Native AI Linux / Glyphd OS
Agent · devices · local compute · protected native capabilities
                ↕
       Master Control + Mold + Grants
                ↕
Gummy OS
Actors · canvas · Gummies · applications · social surfaces
```

The task is to connect these layers safely, not rebuild either one from scratch.

## Product identity

**Gummy OS** is the browser-delivered WebOS and creative playground.

**Actor** is a persistent addressable computational presence that can be opened through the web.

**Agent** is executable intelligence that may operate an Actor under explicit authority.

**Z** is the conversational/control presence available both inside Gummy OS and through a native app or distro panel.

**Gummy** is anything an Actor creates, owns, receives, shares, or operates.

**mygum.my** is the canonical personal address.

## The playground

Gummy OS gives people primitives, not prescriptions:

- canvas;
- windows;
- Actors;
- Agents;
- Molds;
- Master Control;
- Gummies;
- Bowls;
- Links;
- Grabs;
- applications and mini-apps;
- protocols and runtimes;
- Receipts.

The hexagonal interface remains a valuable optional mini-app. Other people may prefer a studio, game world, dashboard, social room, blank canvas, conventional desktop, or interface not yet invented.

Play is the onboarding. People should discover power by making, combining, opening, talking, dragging, sharing, and exploring.

## Recursive future

The platform permits:

- Humans creating Actors;
- Agents helping create Actors;
- Actors commissioning Agents;
- Agents creating Gummies and tools for Actors;
- Actors discovering other Actors;
- multiple Actor surfaces composing a shared page, Bowl, Mold, Gummy, application, temporary canvas, or new Actor;
- created Agents and Actors producing further structures.

This recursion is a feature.

The safety invariant is:

> Every new Actor or Agent receives independent identity, provenance, authority, disclosure, and revocation. Creation never transfers power automatically.

## Security opportunity

The host, native OS, enterprise identity, network, endpoint protection, biometrics, passkeys, and hardware security continue protecting the device and connection.

Gummy OS adds a contained layer where much of everyday work can happen without receiving native authority:

- web content remains in browser or capsule boundaries;
- downloads can begin as quarantined Gummies;
- promotion to native storage or execution is explicit;
- suspicious workspaces can be reset or burned;
- a native Agent can monitor approved security signals;
- every bridge is permissioned and receipted.

This reduces blast radius without pretending the browser or Linux automatically solves security.

The same architecture can become an extraordinary authorized security-research workbench: isolated target Actors, specialized Agents, explicit scopes, disposable environments, remediation roles, verification roles, and replayable evidence.

## Portable life

A person may open Gummy OS from a normal browser, phone, PWA, governed WebView, or the existing AI-native Linux distribution.

A live-USB edition can eventually unfold a portable trusted environment using the host for display, input, network, and compute while restoring only approved Actor state and leaving without persisting unapproved local data.

## The immediate product

The first job is deliberately concrete:

```text
start the existing AI-native Linux distribution
→ open Gummy OS inside it
→ use the persistent Z bar / panel
→ open a personal Actor
→ import a real source Gummy
→ authorize one distinct Agent through one Mold
→ Master Control shows location, scope, and data flow
→ receive a result Gummy without changing the source
→ inspect a complete Receipt
→ revoke the Agent or Mold
→ prove quarantined content lacks native authority
→ close and return to the same understandable state
```

Gummy OS must also keep working independently in a normal browser.

## Opportunity

The personal playground can remain useful and free because the commercial value lies in trusted connection and governance:

- verified native bridges;
- Application Pack design and certification;
- Agent and connector brokers;
- enterprise policy and audit;
- secure runtime pools;
- quarantine, promotion, and evidence infrastructure;
- private, dedicated, sovereign, live-USB, and OEM deployment;
- compatibility testing and support.

## Terminal reality

A person opens Gummy OS.

Their Actor is already there. Z is available without taking over the canvas. Their Gummies, applications, worlds, Bowls, Links, projects, and tools remain where they left them.

They can work directly, talk to Z, attach an Agent through a Mold, open another Actor, combine selected things into a new surface, or build an interface nobody else has imagined.

The system tells them what is local, what is web, what is synchronized, what Agent is acting, what authority it has, and what happened.

Gummy OS does not need to own every model, device, identity provider, application, or server. It must preserve the playground, the protocol, the boundaries, the evidence, and the Human's control.
