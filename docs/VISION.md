# Gummy OS Vision

## The proposition

A person should be able to open a URL, enter full screen, and arrive inside a complete personal computer where files, projects, conversations, applications, connected services, people, agents, and shared work are understandable as one place.

Gummy OS keeps the desktop metaphor because it is an adoption advantage, not a limitation. People already understand folders, windows, applications, dragging, sharing, and trash. The architectural change happens below that familiar surface:

- models are replaceable operators;
- authority is temporary and scoped;
- complex software can arrive with agent-operating knowledge;
- execution occurs in isolated capsules;
- Actors, Molds, Gummies, Bowls, Links, and Grabs are portable protocol objects;
- consequential work produces evidence;
- organizations can impose policy without replacing the consumer system.

## Product identity

**Gummy OS** is the browser-delivered personal computer.

**Gummy** is also the canonical noun for the things created, kept, received, shared, or operated inside that computer.

**mygum.my** is the canonical personal address.

The core object language is:

```text
Actor = who acts
Mold = how that Actor is represented and verified
Gummy = what the Actor creates or operates
Bowl = where Actors and Gummies gather
Link = how they relate
Grab = how a Gummy becomes yours without altering the source
```

A person, company, community, school, family, or creative group may distribute a branded Gummy OS edition while remaining compatible with the protocol.

## The immediate product

The first job is not to build the complete social, enterprise, federation, or runtime network. The first job is to make Personal Gummy OS dependable:

```text
real file
→ bounded Actor request
→ real model route
→ new Gummy artifact
→ Action Receipt
→ survives return visits
```

Once the shell is dependable, Gummy Browser can open `glyphd.com`, Glyphd Desktop can appear through the appropriate application or runtime route, and future tools can enter the same computer without forcing the shell to become their internal architecture.

## Opportunity

The personal product can remain useful and free because the commercial product is not access to a folder icon. The licensable value is the governed meeting layer between intelligence and complicated software:

- Application Pack design and certification;
- model and connector brokers;
- enterprise policy and audit;
- verified runtime pools;
- private deployment;
- regulated workflow packs;
- OEM and embedded Gummy OS editions;
- cross-version compatibility and support.

## Terminal reality

A person opens Gummy OS.

Their computer is already there. Their Actor identity remains stable. Their Mold presents and verifies them. Their Gummies, Bowls, Links, applications, projects, and connected resources remain where they left them.

They can ask an agent Actor to use a file or application. Gummy OS grants only the required capabilities, shows approval where needed, returns a result Gummy, and records an Action Receipt naming the Actor, Mold, Grant, source, and outcome.

The same person can place the result in a private Bowl, publish it to an allowed audience, or Grab another Actor's Gummy into an independent version without changing the source.

Gummy OS does not need to own every model, identity provider, application, or server. It must preserve the protocol, authority boundaries, user ownership, and provenance.
