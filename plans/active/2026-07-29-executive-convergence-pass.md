# Phase 2 — Competitive and Internal Vulnerability Audit

The complete audit is recorded in:

`docs/strategy/2026-07-29-competitive-and-internal-vulnerability-audit.md`

## Market conclusions

Funded competitors are converging on:

- guided natural-language creation;
- optional templates and starter patterns;
- visual drag-and-drop orchestration;
- shared context and collaborative canvases;
- activity, blocker, approval, and usage visibility;
- connected application and computer-use execution.

## Competitive opening

Most systems still center one of:

- the Agent;
- the workflow;
- the vendor workspace;
- the generated artifact;
- the command line/chat request.

Gummy can center the Human-owned evolving object and preserve:

- persistent Actor identity;
- replaceable Agent execution;
- exact Production context;
- Shared Vision and social provenance;
- contribution and economic agreements;
- explicit authority and revocation;
- Return and Receipt;
- Human acceptance before canonical state;
- provider-neutral durable project sovereignty.

## Internal vulnerabilities selected for immediate repair

- blank-canvas paralysis;
- topology visible before the Human goal;
- consequences scattered across technical details;
- friction moving canonical objects from Gummy Box into Composer;
- public product meaning absent from machine-readable delivery;
- no bounded Firefox/WebKit acceptance lane;
- competitor/self-model completeness risk.

# Phase 3 — Delta Analysis and Synthesis

## Current → required delta

| Current state | Required state | Chosen implementation |
|---|---|---|
| Blank Composer is powerful but ontology-heavy | Immediate useful starting point without lock-in | Five optional editable starting patterns |
| Goal exists implicitly in Production/configuration | Human and Agent can see desired outcome and limits | Durable goal/audience/success/boundary Composer brief |
| Safety evidence distributed across nodes/edges | Human can see consequences at a glance | Composer impact/readiness map |
| Gummy Box and Composer require rediscovery | Workspace behaves like one computer | Drag/reference and “Add in Composer” from Box |
| Gummy Box Home is largely a folder view | Familiar continuation surface | Home launchpad with recent work, metrics, import, Composer, attention |
| Server shell is product-invisible | Public record is legible to humans and machines | Changelog, `llms.txt`, structured application record, consistent metadata |
| Deep acceptance is Chromium-only | Browser OS has bounded platform proof | Scheduled/manual Chromium, Firefox, WebKit smoke journey |
| Templates may become opaque automation | Patterns remain Human-owned proposals | Pattern application starts no Run, Work Order, Grant, charge, acceptance, or publication |

## Architecture preservation rule

The new layer must link canonical records rather than duplicate them.

Composer remains the Human representation of the existing Actor Plan and Production configuration. Master Control and Make Production remain the authority and execution boundaries.
